# A few practical project notes

54GUC is open source. Fork it, experiment in your own branches and explore your own ideas. If something you learn or build could help other users, we'd love to hear about it. The tips below may help when sharing an experiment or asking a question.

## Sharing examples

A small synthetic or edited example is often enough for a public issue. It's worth checking screenshots and excerpts for passwords, session tokens, activation codes, device/SIM identifiers and personal network or location details. Full backups and connection History can contain much more than the field you're investigating. A plain description is welcome too. [Security reports](../SECURITY.md) gives the private contact for sensitive questions.

## Trying hardware changes

Radio changes can interrupt a connection. Local access, a backup and a separate development copy make experiments easier to recover from. Keeping the original profile and each router's own settings and History gives you a useful way back and a clearer comparison.

## Sharing a result

Tell us what you tried and what you learned, including anything uncertain. A note about whether an example came from hardware, a simulator or documentation helps the next person build on it. For a code change, a small test showing the behavior is helpful; draft work and open questions are welcome.
